- **ID:** `T0.1`
- **Ola:** 0 (Diagnóstico de solo lectura / tests)
- **Nivel de modelo recomendado:** `ligero`
- **Alto riesgo / Revisión humana:** No (solo crea archivo de prueba sintético; **NO toca datos reales ni `lib/`**)
- **¿Toca archivos protegidos?:** No
- **Hallazgos asociados:** `L1.1`, `L1.3`, `L1.4`, `L2.1`, `L2.4`, `L3.1`, `L3.2`

## Objetivo
Crear una suite de pruebas unitarias aisladas (`test/audit/accounting_repro_test.dart`) usando cajas Hive temporales y `SharedPreferences.setMockInitialValues({})` que reproduzca los 7 bugs contables críticos sin modificar `lib/` ni datos reales.

## Archivos
- **Permitidos:** `test/audit/accounting_repro_test.dart`
- **Prohibidos:** Todo `lib/`, `android/`, `pubspec.yaml`, archivos protegidos, bases de datos reales.

## Contexto mínimo a leer
- `lib/data/transaction_service.dart` (`_processTransfer`, `_revertTransaction`, `deleteTransaction`, `_updateGlobalBalance`)
- `lib/data/credit_card_calculator.dart` (`calculateTotalDebt`, `calculateMonthlyPayment`)
- `lib/data/responsibility_service.dart` (`togglePaidStatus`, `processDebtIncrease`, `syncCardBalance`)

## Prueba fallida y criterio de aceptación
- **Prueba:** Cada test en `test/audit/accounting_repro_test.dart` debe demostrar el fallo actual (ej. `togglePaidStatus` revierte su cambio, `calculateMonthlyPayment` sigue cobrando cuota cuando deuda = 0, `_updateGlobalBalance` ignora `includeInTotal: false`).
- **Aceptación:** Los tests compilan y ejecutan en Docker; documentan los fallos que Ola 1 corregirá.

## Comandos Docker
```bash
docker-compose exec -T flutter-env dart analyze test/audit/accounting_repro_test.dart
docker-compose exec -T flutter-env flutter test --no-pub -j 1 test/audit/accounting_repro_test.dart
```

## Riesgos, retroceso y qué NO hacer
- **Qué NO hacer:** No modificar archivos en `lib/` ni ejecutar sobre el teléfono/datos reales.
- **Retroceso:** `git checkout -- test/audit/accounting_repro_test.dart` o borrar el archivo de test.
